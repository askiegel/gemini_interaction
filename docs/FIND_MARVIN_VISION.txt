Normal Runtime Find Marvin changes
---------------------------------
YOLO/Gemini confirmation, strict OpenCV identity continuity, source stamps,
camera freshness and bearing alignment remain the perception authority.
The normal Runtime observation, pursuit and final-JIT paths no longer call
MarvinTargetRangeAssociation or evaluate_marvin_lidar_standoff. There is no
five/sparse target-return admission, target-distance continuity, sparse
corroboration episode or range-derived arrival/taper in that path.

The existing forward bound remains 0.10 m/s for at most 0.50 seconds. Local
route geometry for that command checks its actual 0.05 m swept segment with
the unchanged 0.45 m radius. Camera bearing is an orientation cue; lateral
translation cannot synthesize target parallax without a fresh camera view.
Existing local bypass uses its existing bounded obstacle-only horizon, not
Marvin depth. All local primitives still use ordinary planning, final-JIT,
exclusive ownership and active Bridge/interlock safety.

A sensed obstruction enters existing STOP/BLOCKED_WAIT. Recovery requires
fresh producer-bound sensing and a new strict camera observation before
ordinary replanning and dispatch. Certified pre-transport forward/turn
collision refusals also enter that existing path. Rotation checks the existing
Bridge-equivalent full 0.45 m footprint before dispatch and while waiting;
this does not change Bridge code, thresholds or monitoring.

No Runtime stop/disable/restart or startup-hold installer is part of this
feature or its tests. Collision/freshness/coverage constants, Bridge client,
interlock/STOP fence, OpenCV tracker and obstacle-phase ownership machinery
remain unchanged. Historic pure range helpers and old diagnostic endpoints
remain separate from the normal Runtime mission route. The old proof
checkpoint range_association field is empty and confers no authority.

Operator-controlled open-space mission contract
------------------------------------------------
The operator explicitly selected mission-start confirmation, with completion
reported as CONDITIONAL on that setup. Marvin must be placed in open space,
with no unrelated object between Mayday and Marvin, for the whole demonstration.
This is trusted operator input, not something YOLO or LiDAR has proved.

The existing parsed intent accepts marvin_open_space_confirmed: true only for
a normal FIND_OBJECT / Marvin mission. Default is false. Non-booleans, other
targets/intents and one-step/centering/guarded-approach test combinations are
rejected. The value is retained on that mission and never enables later ones.
No new endpoint, configuration service, depth system or navigation component
is added. Natural-language text alone does not set the confirmation field.

Prepared parsed-intent example for a separately authorized future mission:
{"intent":{"intent":"FIND_OBJECT","target":"marvin",
           "marvin_open_space_confirmed":true}}
This document does not submit that request or authorize physical motion.

Completion requires a genuine forward collision veto, either before transport
or through the existing certified command-scoped STOP. Turn/strafe/reverse and
sensing-failure interruptions cannot complete. Existing collision geometry must
show that the stopped forward command is blocked and that occupied parts of its
swept capsule lie only in the existing front octant. Side/rear/inner-footprint
intrusions cannot be relabelled target stopping. This is command-safety
classification, with no target-camera/scan association or return-count rule.

After verified stationary STOP, require a newer Gemini identity and strict
OpenCV frame, fresh receipt and centered target within the existing tolerance.
Then obtain another advancing producer-bound native scan AFTER the camera
check, with unchanged freshness and all-octant coverage. The same forward
boundary must still block motion. Recheck controller ownership, inactive,
gait-zero, zero axes and interlock state. Finally execute ordinary terminal
STOP and reverify controller zero and evidence freshness before reporting:
  state: SAFE_APPROACH_COMPLETE
  mission_outcome: safe_approach_complete
  completion_conditional_on: operator_confirmed_open_space
  arrived_at_marvin: false
There is no subsequent movement, retry, target distance or calibrated-arrival
claim. boundary_object_identity_verified remains false. Missing/invalid camera,
LiDAR, controller, owner or STOP evidence prevents successful completion.

Unexpected foreground obstruction remains a negative case. Visible occlusion,
identity/quality loss or changed target alignment prevents completion. The
operator must STOP if the controlled setup is violated. A hidden object that
leaves the same strict Marvin and scan evidence is not observable here: it can
still produce CONDITIONAL completion if the operator's declaration is false.
This limit is explicitly tested, not described as automatic obstacle identity
verification. Unconditional completion remains disabled. Physical collision
protection and STOP are identical regardless of the declaration's truth.

physical robot-reference-to-Marvin surface separations at the intended
arrival stand-off and at farther negative positions. Pair each measurement
with native camera frame/stamp, unpadded proposal and actual padded strict
tracker box; record camera mount/standing pose and resolution. Cover the
supported Marvin orientations and representative partial occlusions.

First establish that the observed box consistently bounds Marvin, rather
than changing background objects. Quantify the separation/pose variability
and an uncertainty margin. Validate a conservative visual decision on
independent held-out observations on BOTH sides of the arrival boundary,
including clipped/incorrect/identity-lost boxes. Account for the existing
maximum forward step, stop latency and unchanged 0.45 m collision envelope.

reuse scan-association uncertainty as visual calibration. No new hardware,
mapping, tracking or navigation subsystem is required.
